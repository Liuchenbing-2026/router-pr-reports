这幅图把进程边界、库调用与网络载荷放在不同位置。This map separates process boundaries, library calls and network payloads.

图为职责与数据流示意，不表示独立机器数量、进程数量或耗时比例。窄屏可在图内横向滑动。Responsibility and data-flow diagram—not a machine count, process count or measured timeline. Scroll inside the figure on narrow screens.

最容易混淆的一点：gRPC 是连线上的通信方式，不是一台服务器，也不负责理解提示词。vllm-chat 是 Router 调用的渲染库；Worker 是接收推理请求的运行服务；模型是最终执行计算的权重与结构。The key distinction: gRPC labels the connection. It is neither a server nor a prompt interpreter. vllm-chat is a rendering library called by the Router; the worker is a running inference service; the model is the weights and architecture used for computation.
